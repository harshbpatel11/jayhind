## How to regenerate this whole baseline

```bash
# Tests
(cd jayhind-client-back && npx jest --silent)
(cd jayhind-admin-back && npx jest --silent)

# Routes
(cd jayhind-client-back && npx ts-node -r tsconfig-paths/register scripts/dump-routes.ts > /tmp/routes.txt)

# Schema (reads .env in each repo for credentials)
mysqldump -u root -p"$DB_PASS" --no-data --routines --triggers --skip-comments \
  --ignore-table=jayhind_client.SequelizeMeta --ignore-table=jayhind_client.SequelizeData \
  jayhind_client > jayhind_client-schema-<date>.sql
mysqldump -u root -p"$DB_PASS" --no-data --routines --triggers --skip-comments \
  --ignore-table=master_hub.SequelizeMeta --ignore-table=master_hub.SequelizeData \
  master_hub > master_hub-schema-<date>.sql

# Performance (mutates a scratch DB - do not point at jayhind_client)
# see MASTER_DEVELOPMENT_PLAN.md section 20.6/Qb.5 for the full qa-volume.ts recipe
```

All of the above are read-only against the live dev databases except the
performance baseline, which is explicitly scratch-DB-only per Qb.5's own
design.
